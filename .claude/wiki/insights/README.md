# Team-shared Insights

This directory holds insights an individual developer published via
`/h-publish-insight` — patterns the local Insight Layer detected on
their machine that are worth sharing across the team.

## What goes here

Files are auto-generated by `/h-publish-insight`, named:
```
<YYYY-MM-DD>_<insight-short-id>_<slug>.md
```

Each file documents one observed pattern:
- **What we observed** — the pattern in plain language
- **Evidence** — supporting data (failure counts, file paths, etc.)
- **What we did about it** — rule change applied? Wiki updated? TBD?
- **What you should know** — actionable takeaway for teammates

## Why this exists

The Insight Layer's raw data (`.claude/runs/local_intel/insights.jsonl`,
`events.jsonl`, `failure_memory.json`) is gitignored — that data is
single-machine local for performance and privacy reasons.

When a developer hits a pattern (recurring failure / co-edit cluster /
decayed knowledge / etc.) and decides it's team-worth, they invoke
`/h-publish-insight --insight-id <id>` to elevate it to this directory.
The doc enters git and propagates via normal PR flow.

**Publishing is always a deliberate manual act**. No detector, hook, or
command auto-fires `/h-publish-insight`. This prevents the team wiki
from being polluted by half-baked pattern noise.

## What does NOT go here

- Production incidents → `.claude/wiki/incidents/` (different concept; incidents
  are factual events with root cause + fix, insights are observed patterns)
- ADRs → `.claude/wiki/wiki/architecture/adr/` (decisions, not observations)
- Recurring task templates → the relevant wiki domain index
- Personal notes → don't publish; keep in local `insights.jsonl`

## How to publish

```bash
# Find an insight worth sharing
python3 .claude/scripts/local_intel/insight_writer.py query

# Preview the proposed doc (no write)
/h-publish-insight --insight-id <id> --dry-run

# Publish + suggest the git commit command
/h-publish-insight --insight-id <id>
```

After publish, the insight's local status moves to `published` (terminal),
so it won't surface again in `/h-context-check` reminders.
